## Portfolio direction (provisional)

- **Two directions:** customer-facing software delivery versus AI application engineering. These are hypotheses until verified against employer sources.
- **Primary reader:** internship reviewer; secondary reader: potential project collaborator.
- **Promise:** For an internship reviewer, make it easy to see implemented projects, contribution, code and checks.
- **Voice:** curious, practical, clear. **Character:** Creator with evidence-first presentation.
- **Design A:** restrained, modernist-inspired grid for quick scanning. **Design B:** expressive technical notebook with clear paths to evidence.
- **Choice:** A provisionally; compare with a peer. Add a cited real visual reference before finalizing.
- **Persuasion:** inspectable code/checks and candid limitations. Neither implies guaranteed employment or fabricated authority.

## User stories and checks

1. As a reviewer, I can open an individual project repository and inspect a real test result. **Check:** both links work and the test evidence is real.
2. As a reviewer, I can distinguish personal contributions, team contributions, starter code, and AI assistance. **Check:** case studies label each accurately.
3. As a reviewer, I can distinguish implemented behavior from planned features. **Check:** all project claims match current evidence.
4. As a reviewer, I can locate source dates and original employer pages. **Check:** three role cards link to verified pages.
5. As a reviewer, I can locate résumé, actual GitHub and LinkedIn profiles, and professional contact. **Check:** links exist and work when added.
